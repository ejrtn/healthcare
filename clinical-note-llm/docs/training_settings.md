# 학습 설정과 정한 기준

SFT 9번(Qwen 7번, Llama 1번, 2026-10-27 ~ 10-30) 모두 아래 설정 그대로다. 코드는 `kaggle/02_sft.py`.
학습 설정을 바꿔 가며 비교한 실험은 없다. 결과가 이상하면 설정이 아니라 데이터를 고쳤다.

## 무엇을 학습하나

- 목표: 다음 토큰 예측 손실(cross-entropy). 입력(차트 + 대화)을 보고 정답 진료기록(4구역 JSON)을 맞힌다.
- 손실은 정답 기록 부분에만 건다(TRL prompt-completion 형식). 입력은 맞히지 않아도 된다.
- 원래 모델은 4bit로 얼려 두고 LoRA 어댑터만 학습한다(QLoRA).

## 설정과 정한 기준

정한 기준은 세 종류다. ① GPU 제약 ② 데이터를 재서 정함 ③ 흔히 쓰는 기본값. 대부분이 ③이다.

| 설정 | 값 | 정한 기준 | 종류 |
|---|---|---|---|
| 4bit 양자화 (QLoRA) | NF4 | T4 메모리 16GB로는 3B 모델 전체를 학습할 수 없음 | ① GPU 제약 |
| fp16 | | T4는 bf16을 지원하지 않음 | ① GPU 제약 |
| 장당 배치 1 + 4번 누적 | 실질 8건 (GPU 2장) | 기록이 길어(최대 약 4,700토큰) 장당 1건이 한계. 누적으로 8건을 맞춤 | ① GPU 제약 + ③ |
| 최대 길이 | 5200 (차트 + 대화) | 학습 데이터에서 가장 긴 예시를 재고, 잘리는 예시가 없게 정함 | **② 데이터 측정** |
| LoRA를 붙인 곳 | 모든 선형층 (q·k·v·o, gate·up·down) | QLoRA 논문에서 일부 층만 붙이면 전체 미세조정 성능에 못 미친다고 보고 | ③ 논문 권장 |
| 학습률 | 2e-4 | QLoRA 논문과 대부분의 예제가 쓰는 값 | ③ 관례 |
| LoRA r / alpha | 16 / 32 | 흔한 기본값. alpha는 r의 2배로 두는 경우가 많음 | ③ 관례 |
| dropout | 0.05 | 흔한 기본값 | ③ 관례 |
| 에포크 | 3 | 데이터가 100건 안팎일 때 흔히 쓰는 값 | ③ 관례 |
| 학습률 스케줄 | cosine, 처음 5% 워밍업 | 흔한 기본값 | ③ 관례 |
| seed | 0 | 값 자체는 의미 없음. 고정해서 재현 가능하게 함 (7차부터 `--seed`로 바꿔 흔들림을 잼) | 재현성 |
| Llama만: Liger kernel + expandable_segments | | Llama는 은닉 차원(3072)이 Qwen(2048)보다 커서 메모리 부족. loss 값은 같음 | ① GPU 제약 |

## 결과를 보고 판단한 기준

학습마다 테스트 120건으로 기록을 생성해 아래를 같이 봤다. ROUGE가 올라도 근거 검사가 나빠지면 실패로 보고 데이터를 고쳤다.

| 기준 | 무엇을 보나 |
|---|---|
| ROUGE-1 (전체 + 구역별), ROUGE-2·L | 내용 단어·표현·순서를 정답만큼 썼나 |
| 근거 없는 숫자 | 입력에 없는 숫자를 썼나 |
| 지어낸 나이 | 대화·차트에 없는 나이를 썼나 |
| 근거 없는 검사 | 입력에 없는 검사 이름을 썼나 |
| JSON 성공·잘림 | 형식이 깨지지 않았나 |

- 학습 설정은 테스트를 보고 바꾸지 않았다. 디코딩의 frequency_penalty 0.4는 검증 20건으로 골랐다.
- 데이터를 고치는 판단(지어낸 나이, 차트 누출)은 테스트 결과를 보고 했다. 엄밀히는 검증 세트로만 판단했어야 한다.

## 빠진 것

- 기본값이 이 데이터에 맞는지 확인하지 않았다. 에포크 2·4, r 8·32, 학습률 1e-4·3e-4 등을 비교한 적이 없다.
- 비교한다면 검증 손실보다 **검증 세트의 ROUGE와 근거 검사**로 고르는 것이 맞다. 손실이 낮아도 기록을 지어낼 수 있다.
